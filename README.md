# Сверка для Android

«Сверка» ведёт инвентаризацию оборудования офлайн. При первом запуске список ведомостей пуст.

## Проведение инвентаризации

1. В разделе **Ведомости** нажмите **Добавить офис**, чтобы создать пустую ведомость по названию. Для заполнения нажмите **Добавить оборудование**, введите номер в строке поиска по коду или считайте его камерой. Готовую таблицу можно загрузить через **Загрузить файл**. Выберите CSV, XLSX или TXT. Для Excel укажите лист. В предварительном просмотре проверьте строку заголовков и назначение столбцов. Каждый импорт создаёт отдельную ведомость.
2. Нажмите **Указать место** и введите кабинет или площадку. Приложение добавит это место к следующим отметкам. У каждой позиции есть своё поле для фактического места и примечания.
3. Нажмите **Сканировать код** для штрихкода или QR. Для обычной печатной надписи нажмите **Считать S/N**, наведите камеру и нажмите **Считать**. Коснитесь изображения для фокусировки. Можно выбрать сохранённое фото.
4. Перед принятием распознанного текста сверьте сходные символы с наклейкой. Поле допускает ручное исправление. Похожие номера из базы выводятся как отдельные варианты. Для внесения нового S/N в известное устройство откройте его карточку, считайте номер, проверьте флажок «Позиция найдена» и сохраните карточку.
5. По общему номеру Inside выберите одну позицию либо подтвердите весь комплект. Неизвестный код появится в списке **Вне базы**. Из него код можно привязать к конкретному устройству.
6. Через **Отчёт** сохраните Excel или выберите приложение для отправки. В Excel остаются исходные столбцы, добавляются отметки, фактические номера, места, время в UTC и примечания. Найденные строки подсвечиваются зелёным. Для неучтённого оборудования предусмотрен лист «Вне базы».
7. Для переноса работы на другое устройство сохраните **Резервную копию** и загрузите полученный JSON через **Сменить → Загрузить файл**. Повторную инвентаризацию можно начать по той же базе отдельной ведомостью. Уточнённые серийники перейдут в новую сверку.

В TXT поддерживаются списки по одному номеру в строке. В табличных текстовых файлах доступны запятая, точка с запятой, табуляция и вертикальная черта. Импорт читает UTF-8, UTF-16 и Windows-1251. Для идентификаторов Excel сохраняются текстовые ведущие нули и числовые форматы вида 000000. Если Excel уже округлил длинный числовой идентификатор при вводе, исходные цифры доступны только в первоначальной выгрузке. Лимиты импорта составляют 32 МБ, 25 000 позиций и 160 столбцов.

## Сборка и подпись

Проект предназначен для Android Studio или Gradle с JDK 17, Android SDK Platform 35 и Build Tools 35.0.0. Минимальная версия Android — 8.0 (API 26). Комплект моделей Google ML Kit для штрихкодов и печатной латиницы входит в пакет. CameraX подаёт кадры на распознавание. Для чтения файлов используется системный выбор документов Android. В итоговом манифесте отсутствует разрешение INTERNET.

Для первой сборки Gradle скачивает зависимости. В macOS или Linux выполните следующие команды в каталоге проекта.

```bash
export SVERKA_KEYSTORE=/absolute/private/path/sverka-release.p12
read -rs -p 'Пароль ключа: ' SVERKA_STORE_PASSWORD
echo
export SVERKA_STORE_PASSWORD
./gradlew :app:assembleRelease
```

Готовый подписанный файл находится в `app/build/outputs/apk/release/app-release.apk`. В Windows используйте `gradlew.bat` и те же переменные окружения. В архиве владельца находятся PKCS#12, пароль и alias. Для обновления установленного приложения используйте этот же ключ, идентификатор пакета `ru.it.inventory` и увеличенный `versionCode`.

## Проверка

Интерфейс, импорт, сопоставление и выгрузка находятся в `app/src/main/assets`. Примеры для тестов в `app/src/androidTest/assets` содержат вымышленные коды.

- Для браузерных сценариев установите Node.js, Playwright и Chromium. Выполните `npm install --no-save playwright`, `npx playwright install chromium`, затем `node qa/web.cjs`. Можно передать путь к установленному Chromium через `CHROMIUM`, каталог для результатов через `QA_OUTPUT`.
- Для независимой проверки экспортов укажите одинаковый каталог в QA_OUTPUT и команде `python qa/verify_exports.py <каталог>`. Требуется пакет openpyxl.
- Для интеграционных сценариев подготовьте отдельный тестовый профиль Android 11 или новее. Задайте те же переменные подписи, выполните `./gradlew :app:assembleRelease :app:assembleReleaseAndroidTest` и установите через adb оба APK. Команда ниже проверяет возврат content URI системного выбора файлов, запись отчёта, QR, Code 128 и OCR. Тест подставляет свои документы в стандартные ответы выбора файла и использует реальные библиотеки распознавания.
- Вторая команда проверяет холодный запуск и передачу файла системному меню публикации. После первого набора выполните `adb shell am force-stop ru.it.inventory`.

```bash
adb shell am instrument -w ru.it.inventory.test/ru.it.inventory.qa.DeviceChecks
adb shell am force-stop ru.it.inventory
adb shell am instrument -w -e mode resume ru.it.inventory.test/ru.it.inventory.qa.DeviceChecks
```

Для проверки видеопотока запустите Android Emulator с параметром `-camera-back imagefile:/absolute/path/to/qa/camera.png`. Затем выполните `adb shell am instrument -w -e mode live ru.it.inventory.test/ru.it.inventory.qa.DeviceChecks`. На испытательной карточке 640 × 480 повторяются QR-код `QA-QR-59041` и печатный номер `XT74-5823`. Это позволяет снять этикетку при портретной ориентации. Для отдельной ручной проверки Code 128 используйте `qa/camera-code128.png` в том же параметре эмулятора. Создайте тестовый офис и нажмите «Сканировать код». После чтения кода «252» откроется карточка добавления оборудования.

ExcelJS распространяется по лицензии MIT, её текст приложен в каталоге `assets/vendor`.
